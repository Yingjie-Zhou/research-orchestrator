# 自适应约束

把执行约束当作实现可靠验收的工具。默认流程不能通过新增回执、修复轮次或逐级门阻止预算内仍有信息价值的研究。以下分层用于新合同与允许调整的现行默认值；不追溯取消用户明确的限制或原任务中的既有违规。

## 什么必须保持，什么可以调整

| 类型 | 例子 | 决策方式 |
|---|---|---|
| 授权及明确硬限制 | 可访问环境、外部消息、用户CPU/RSS/墙钟或样本上限 | 继续遵守；超出须有相应授权 |
| 证据与科学不变量 | 原数据、独立来源、原分母、随机律、冻结记录、目标定义、模型有效域 | 保留；任何实质变更都显式登记并重验受影响范围 |
| 可调整默认值 | 预列文件数、查询次数、检查清单、巡检间隔、准备软节点、默认修复次数 | 在原授权/科学范围/硬预算内按必要性调整，简记理由与影响 |
| 展示及元数据 | 字段漏记、路径笔误、索引与回执格式 | 对应所有者更正，核对身份，不消耗新科学样本 |

把“会影响结果或权限”的限制写清楚；其余采用目的或停止条件表达。不要把历史单案参数、建议顺序或模板字段转换成所有项目的硬门。

## 流程偏差的处理

先判断偏差是否改变原始证据、来源可信度、运行版本、样本选择、目标口径、模型域或资源权限。

- **仅展示或关联字段有误，实际来源可唯一核对：**对应所有者更正元数据，保留原记录和更正依据，继续核对与验收。原独立报告只能由审查员更正；作者可以补自己的回执，不能改报告冒充审查员。
- **默认流程需补必要读取或检查：**登记依赖及因果理由，计入实际成本，在原范围内继续。不自动新开研究轮、重置任务或打断健康执行。
- **实现或版本改变，但问题、样本及模型定义未变：**保存差异和旧失败，重冻受影响产物，在原预算内做有依据的回归/增量审查，未变证据复用。
- **改变科学问题、模型、样本或观察规则：**作为显式修订或新问题，说明增量、可比性及预算来源；遵循原授权。不能把改种子、放宽门或重选样本写成修复。
- **来源不能认证或触及明确硬限制：**保持相关范围未接受，停止触及该边界的动作，说明影响与最小恢复条件；可独立支持的范围继续处理。

流程异常、数值失败、物理模型失败和信息不足分别记录。某份交付不满足原流程时保留其原处置，但不能从流程偏差直接推导数值必错；也不能从“只是流程”直接推导科学可接受。

## 读取与审查以因果依赖为界

任务允许读取被选环境和版本中，为实际生产者/消费者所需的依赖及诊断证据。预注册目标、模型、样本、预算与声明边界；文件清单可以记录执行时实际发现的依赖。

审查员需要一个额外头文件、类型定义、原始输出或小检查时，可在既有授权、原问题和预算内自行选择并说明原因。无须为每个检查先向作者申请；作者不能因此控制独立审查结论。大规模重跑、外部访问或明确被禁止的操作仍按原权限处理。

对稳定冻结输入核对过身份后复用证据索引；新版本、身份漂移、实际消费者不一致或组合声明变化时才补核对应依赖闭包。不每次唤醒重算所有哈希、不重复整组审查、不把状态写入当作科学成功。

## 修复与预算

用“明确原因、原预算内、验证能改变决策、重复失败时转向/停止”控制修复。易形成反复采样、自动重启或大算量重试的任务，可额外设有限次数上限。没有这类风险时，不为常规依赖补读和字段纠正另设一两次死限。

计量粒度与成本风险匹配：廉价只读操作可使用现有环境控制；昂贵试验须有可靠硬上限与累计余额。未计量推理/封存成本列 unknown，不能填零；它不自动阻塞有可靠CPU/RSS/墙钟余额的操作，也不让全资源审计被标为PASS。相关硬预算余额不可靠时，不启动可能超额的计算。

准备、冻结、审查等阶段CPU分配默认是总额内的计划，可依据真实必要性调配并记录，不额外制造数秒级阶段硬门。总资源、样本和确有风险理由的单次控制硬上限继续有效。用户明确固定的阶段上限或既有冻结合同的硬上限，必须按原权限处理，不能借调配默认值越过。

准备节点是评估点。迟到后判断剩余成本、信息价值及硬预算，不把软节点越过解释成物理不可行。元数据更正计入真实时间；不扣一个并未执行的科学样本或因果修复次数，也不擦除历史成本。

## 调度与最小记录

一个集成负责人是完整链的作者，不能变成所有独立问题都要串行等待他的规则，也不能承接主控的全部整理、催办与重复审查。科研专家并行须有信息增量或具体依赖用途；简单执行任务可以因为能减少主控或集成作者负担而派出，不必假装产生新科学结果。使用用户指定作者配置，简单任务降低的是合同和审查负担，不自动降低模型档位。巡检优先有变化与会影响近期决策的任务，稳定项保留下一检查时间；显式要求全组巡检时仍必须全覆盖。

把相关目录核对、清单整理和元数据修正合并成一个有限支持任务，给出清楚的所有权、接收者和可核对输出。对应接收者核对产物与科学身份是否变化，不需要为字段修正另派独立科研审查员或逐条升级主控。审查员自己的报告只能由审查员更正；普通作者支持任务不能代改。健康研究占满并发资源时，支持项排队或合并到已授权支持任务，不抢占、打断研究。

日常缺项直接返回其所有者；科学口径、硬预算/权限或跨合同取舍才升级。来源认证和最终科学判断仍由承担相应责任的角色依据真实证据核对。分工和上下文缩减见 [职责与减负](role-boundaries.md)；职责字段不授予额外工具或外部消息权限。

一次偏差的记录可以只是“发生什么、原因、影响的身份/范围、处理、成本、继续或停止”。复用当前任务、review或状态记录即可；无新增风险时不专门创建一套例外审批、顾问咨询或多份重复回执。

## 判断示例

| 情境 | 合理处理 | 不能推出 |
|---|---|---|
| 需要第4个文件，而3个只是默认清单 | 核其同版身份与必要性，登记补读后继续 | 科学结果失败或必须新开轮次 |
| 需要第4个文件，但用户明确只允许3个 | 保留限制，使用允许证据推进独立部分；必要时说明来源并请求最小调整 | 技能自行授权第4次读取 |
| 审查员发现需要一个未预列的小控制 | 在允许资源内检查并写入报告；真实硬禁令另处理 | 未预列就不独立或自动流程失败 |
| 回执缺报告SHA，原字节和完成轨迹一致 | 由所有者补回执身份并核对，继续验收 | 作者可以重写独立ACCEPT报告 |
| 格式修正后代码/数据/结论身份未变 | 保留更正与实耗，复用已审科学范围 | 必须重抽样或重跑全链 |
| 主控被交接包和回执整理占用，可用作者资源充足 | 用指定作者配置派一个合并的支持任务，核对真实产物 | 简单任务必须主控亲做或必须再建科研审查 |
| 主控工作减少，但集成负责人开始整理全体报告与催办 | 作者补齐完整包，支持整理检查材料，专家交付走各自接收者；集成作者回到共同链 | 换一位负责人就消除了瓶颈 |
| 原科学硬预算耗尽，提出新名字续同一试验 | 保存失败并停该方法，评估真正不同且有授权预算的问题 | 默认次数可调等于硬预算可重置 |

## 工程停点与时钟语义

有据工程修复以科学不变量、累计硬资源余额和信息价值为界。优先问题已有用户放宽时，次数只计入诊断，不制造逐错误授权或咨询循环；无原因盲重试、硬余额不足、模型/样本/访问改变仍停止相应动作。程序在运行的I/O或等待计入硬墙钟，未运行程序的交接/模型/用户等待单列；准备/审查软节点用于评估。现有连续硬时钟不得隐式改为活跃时长或重置，前瞻变更由相应授权者登记，旧到期/违规保留。接口和输入见 [稳定接收与分开计时](receiving-and-clocks.md)。

## 执行者自主权与完整修复

新合同默认给作者在目标、科学不变量、写入所有权和可靠总预算内选择方案、补读依赖、修改、自检并交付的权限；不要把旧单案文件数、阶段秒数和修复次数固化成普遍门。普通可逆工程修改按受影响路径验证即可，科学来源/数值语义/模型/样本/观察量改变才做对应冻结与独立复审。同问题的成组修复在原任务内闭环，不为每个小改新增咨询/预注册/审查链。实质停滞按[持续派工与 Pro 解阻](active-dispatch-and-pro.md)主动咨询用户指定GPT-6 Pro，并继续不受该卡点影响的任务。
