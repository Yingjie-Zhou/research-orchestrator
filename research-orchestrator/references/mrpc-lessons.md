# MRPC 案例与纠偏

来源是 2026-10-04 对「MRPC计数率项目主控」的读取与评价，以及该项目已保存的阶段报告、各组审查流程和用户采纳的 Pro 方向意见。这是历史案例，不是新项目的执行状态。

## 原任务和保留的长处

项目要判断：给定气体、六气隙结构、供电接点、照射及性能要求，降低玻璃电阻率能带来多少条件计数率收益，主导限制何时改变。不能预设必有内部最优电阻率。

主控把源与近源场、输运、电极供电恢复、可观测性、理论边界和实现审计分给不同组。作者冻结后由独立审查员审查，主控核对来源与已接受范围，失败和未知不被成功小测试覆盖。这些能力可迁移。

阶段报告给出有具体决策意义的条件量：同一旧静态模型下，ρ从10^7降至10^5 Ω·m的名义容量比约1.07023；完整平均等效负载增加约7.02%即可抵消该改善。这把“低阻是否值得”转成了目标敏感性问题。该数字不适用于任意几何、事件律或实际器件，也不是本技能重新计算的结果。

## 原流程的失效方式

后期出现从场查询、getter、碰撞 tuple、等待时间提议逐项续接的组织方式。局部验收增加，但共同版本、物理时钟、离子源、信号与负载仍没有形成完整历史。

具体教训：

- 当前各组的“最新”片段可能分别来自不同 SDK、几何、常数或源表示；拼接后不会自动成为最新版全链。
- 原生粒子/后代栈的处理顺序未必是共同物理时间顺序。动态共享场若被父粒子推进到未来，较早出生的后代可能读到不相容状态。源码顺序揭示的是风险条件，不能据此断言已有轨迹已经出错。
- 固定源的传递与恢复比较，和材料改变后重新生成事件的总效应不同；两者都可有价值，必须分别标明。
- 元数据回执或刷新门不能证明场/输运评估真实成功；实际返回、完整源和消费者记录要能够核对。
- 任意“只读3个文件”限制可让必要依赖读取成为流程异常。应限定已选环境的因果依赖闭包、计算次数及总资源，保留原异常历史但区分它与科学错误。
- 独立审查也需要可信来源和有限范围。作者自写报告、换审查员追通过或主控重复整组审查，会破坏职责边界或增加成本。

## 采纳的组织调整

由一位集成负责人完成：

`事件前状态 → 实际高层生成器 → 同次轨迹/信号/负载 → 被动恢复 → 下一事件前状态`

先获得一条有限基线，再在同一合同下做一对材料干预。专家只为实际路径中的明确缺口提供支持，停止给每个组自动续一轮。

进一步的组织纠偏：完整链负责人直接实施共同 history，作者补齐自己的证据包，支持执行者整理冻结/来源/成本清单与状态，独立审查员负责科学审查。完整链负责人处理版本、单位、物理时间、源与消费者的真正组合问题；主控处理方向、共享预算和总体终点。当前小规模项目复用已有角色，避免给完整链负责人增加全体专家的催办、打包和重复审查工作。只移动这些工作会复制原瓶颈；减负同时看主控与完整链作者。

事件内背景冻结可以作为明确的第一版近似；事件之间按照同源记录真实时间推进。气体自场、驻留离子、浮置电荷、未完成源尾和读出记忆分别保留或明确限定适用域。不能把尚未生成的未来源默认为零来继续下一事件。

一对记录可支持条件差异、条件无差异或不可识别；不直接给出总体效率、实际 Hz、完整流光终态或最优材料。

## 不固化的项目参数

原项目中作者曾使用 `gpt-6.1-sol/xhigh`、审查员使用 `gpt-6-luna/high`、宏观顾问使用 `gpt-6-astra/xhigh`。这些是当时用户和项目的角色配置，不是此技能的必要依赖。

本技能创建后的用户校正：简单任务也适合派出，以减轻主控压力；作者继续使用6.1 Sol/xhigh。该明确偏好已成为当前用户的作者默认配置，审查与顾问仍分别配置。其他用户或项目可明确覆盖。组织上的调整是让主控负责决策与轻量验收，并合并派出必要的整理工作；不把所有简单工作都收回主控。

原最新集成建议包含900秒累计CPU、4.5 GiB峰值内存、3600秒原生控制墙钟及6工时软节点。这些预算服务当时的有限原生短链，不应照搬到其他规模或风险的研究。

字母组名、轮次、线程 ID、主机路径、固定误差门和 MRPC 专属派工脚本不进入通用合同。新项目从自己的目标、现有实现、资源和用户要求推导。

## 迁移时的情境检查

| 当前材料 | 合理决策 | 需要保留的边界 |
|---|---|---|
| 三组 getter 已通过，实际高层运行入口存在，仍无共同记录 | 给一位负责人一个从输入到目标的有限集成合同 | 局部通过不算L1完成 |
| 缺实际电子学标定，但模型与记录可执行 | 用声明的共同读出规则或参数集推进条件比较 | 实际效率与Hz仍未知 |
| 一臂在有效域外或观察窗有未决源 | 保留失败/未决和原分母，判断该近似是否还可识别 | 不能重抽追通过或把域外算零响应 |
| 读取一个未预列的同版必要依赖，科学结果尚未判错 | 判断是可调整默认值还是明确硬限制；允许的补读简记理由，旧严合同异常保留 | 不将默认清单当封闭范围，也不自动推导数值错误 |
| 独立报告的回执字段漏记，但原报告与审查完成轨迹可唯一关联 | 由对应所有者补元数据，主控核对后继续验收 | 不改独立报告字节，不重跑原科学样本 |
| 主控压力来自清单、交接包和元数据整理 | 同配置作者承担一个合并支持任务，主控核对产物和身份 | 必须亲做、自动降档或每个字段都建独立审查 |
| 增设集成负责人后，仍由他重读各组原报告、补回执和催办 | 作者交完整包，支持整理检查表，独立审查保留原职责；完整链作者只接必要交付并处理组合问题 | 新增一层管理自动提高速度 |
| 所有支持组已结束，集成负责人健康运行 | 保持原任务，支持组按具体接口缺口触发 | 不为维持并发数量新造任务 |

验收这套组织方法的重点，是它能否产生共同、可复现、会改变目标判断的记录，以及为此花费了多少时间和资源。
