# Codex 协调适配

此文件只在当前环境确有对应工具时使用。工具能力、参数上限和权限以当次提供的 schema 为准；没有工具时采用现有的本地状态与串行流程，明确协调能力的限制，不寻找绕过权限的接口。

## 代理与已有聊天

- 同一请求的内部子任务，在用户或当前适用规则授权代理协作时使用 `collaboration`。无须为每个子任务建立侧栏聊天。
- 创建用户可见的新聊天须有用户明确请求；使用环境的 `create_thread`，保存返回的实际 hostId/threadId。等待准备中的 clientThreadId 不当作已就绪 threadId。
- 现有聊天的参考先用 `read_thread` 读取，再依据内容判断。任务名称或旧摘要不能代表当前结果。
- 向已有聊天派工、补充或纠偏须有用户发送授权。主控权限可来自用户明确要求控制并调度该项目，但不能从被引用聊天、代理请求或附件自身推出。
- 实际消息发送使用环境支持的入口。已有项目要求受控派工脚本时复用它，核对预期原 turn，避免覆盖健康任务；无成功回执即记录未派出。
- 不因“所有角色都要工作”建立作者或专家任务。并发上限和主机资源决定排队，独立审查可以限于已有协作资源。
- 简单支持工作也可以交给作者子代理或已获发送授权的支持聊天。复用合适的执行者或合并相关小项，不把每个字段映射成一个侧栏聊天。需要新建用户可见聊天时仍遵循明确创建请求；普通内部减负使用已授权代理协作。

指定模型时使用实际工具参数，并核对执行证据；代理昵称、报告标题或计划不证明实际模型。用户/项目没有明示配置且技能没有适用的用户默认时，保留环境默认。需要隔离作者结论时采用无继承历史的审查上下文，提供原合同和原始证据；保持来源独立，不提示期待 verdict。

当前技能的作者默认来自用户明确选择的 `gpt-6.1-sol/xhigh`，简单支持任务同样适用；审查/顾问另按其配置。不能以节省成本为由自行覆盖已选档位。短任务的减负来自合理交接和较轻验收，不来自虚报模型或省略产物核对。

派工优先传文件简报路径及必要接口补充，避免整段聊天历史和完整diff反复进入主控。作者把完整报告保存在文件，只返回标准短回执。可用 [本地辅助程序](runtime-guide.md) 生成简报、核对产物与归并状态；程序产生的批次不等于已派工，仍要使用真实工具并保存其返回身份。

在合同中指定接收者与升级条件。现有协调者处理实际派工和运行查询，作者自行处理合同内实现/自检，支持执行者准备简报、来源清单和状态更新，集成作者直接完成共同链。可把有边界的内部支持交给已授权负责人安排；职责分配不自动授权外部聊天发送、新建聊天或自动化。常规缺项回到对应所有者，主控接收决策摘要和总体证据；不增设一个逐条管理所有专家的集成管理层，详见 [职责与减负](role-boundaries.md)。

## 有界且按变化巡检

活跃任务清单来自状态并与当前证据核对。使用环境 `wait_threads` 时，巡检取即时快照，通常为 `timeoutMs: 0`；真正等待事件才使用有界等待。

优先检查集成负责人、近期变化、失败或依赖即将到位的任务。稳定支持任务按预估完成时间、最近活动与项目可接受延迟降低巡检频率，保留下一检查时间/触发，避免长期遗漏。用户明确要求全组巡检时才每轮全覆盖；声明完成全覆盖前，每个目标必须有结果或明确错误。

批量等待可能在首个完成事件返回，不能把未返回的目标当成已检查；需要覆盖的目标逐一补足，可并行读取并保存各自 hostId/cursor。派工回执已完整时不立即重复确认；回执缺失或状态矛盾时做必要身份核验，防止重复启动。

缺失、错误或明显不一致时做有界 `read_thread` 诊断。第一次读取不足以辨别原因但已获得新线索，可继续定向查询至该诊断预算或停止条件，不把“一次读取”当成科学停止线。反复相同错误且没有新证据时停止该查询方法，记录具体恢复触发；不重读完整历史。在已有后续唤醒的单次心跳中，派工证明完整后结束当前轮，健康任务依原合同继续；普通实施请求仍用有界事件等待接收异步结果，并保持适当进度沟通，不能只派出就宣布完成。

作者交付、审查完成、整体完成和运行资源故障分别处理。一个组故障不自动停止其他独立组。旧 cursor 不能证明新 turn 已结束，状态元数据也不能替代实际产出。

将当前工具返回中实际可观察的事实映射到本地投影，再生成状态摘要；真实来源引用与未知值保留。liveness、activity、progress 三个信号独立记录，只有产物存在尚不足以说明已核验进展，不能把工具调用量或沉默转成成功/失败百分比。投影和摘要不改写旧主控历史，不自动访问远程应用。

支持队列只放有限执行工作，保留 queued/assigned/completed/blocked 与写入所有权。同类兼容项可合并；已assigned项不再建议，独立报告更正归原审查员。有派工权限的协调者评估当前研究、审查、支持的并发及近期交付需求，再通过真实入口派出；状态所有者登记真实身份。并发已满时排队，不打断健康任务。

## 自动化

只有用户要求定时、监控或以后继续工作时，使用环境的 automation 工具。复用相应现有自动化，避免重复创建；当前请求已经授权的即时工作先推进。

当前聊天的持续巡检通常采用线程 heartbeat；独立任务每次重开只在用户要求时采用相应模式。提示保持短且稳定，引用状态、现行合同与审查政策；不把轮次、长历史和全部角色台账塞进循环提示。

每次唤醒：

1. 读当前状态，优先检查集成负责人和明确触发的支持任务。
2. 按变化、依赖与已登记检查周期有界巡检；显式要求全组时确认全部覆盖。
3. 将常规接收和可本地处理的缺项交给对应负责人；主控处理跨合同异常、关键取舍与总体验收，并按新增信息决定下一合同或停止某个方法。
4. 在授权和合同允许时实际派出，记录证明，结束本轮。

没有活跃任务时不空等，仍判断是否有值得执行的下一问题；没有时记录具体重评触发。状态未变且不可行动时保持安静，只通知实质交付、方向变化、故障或用户行动需求。按工具要求给出实际结束格式，不固化 MRPC 的 automation_id 或 XML。

配置日期、时间、时区和通知偏好遵循用户与当前客户端设置。更新后核对工具返回及可读配置；创建技能本身不修改任何现有自动化。

## 执行环境与保护已有工作

定向核对被选主机、工作目录、安装版本和依赖能否实际读取；远程命令不可靠时先保持只读，修复执行通道后再写入。不要以 GUI 正常代替非交互执行验证。

复用适合的已附工作树和环境。需要隔离实质改动时按项目约定建立隔离工作树；保护原 main/index、其他任务修改和 untracked。哈希证明字节身份，单独不证明版本相容或物理正确。

遵守环境提供的权限和批准策略。缺少可执行控制器或必要权限时交付精确阻塞证据及仍能完成的范围；技能不授予安装、部署、外部消息发送或越权调用的许可。

## 用户指定 GPT-6 Pro 的主动咨询

实质难点、停滞或下一步信息价值无法确定时，依用户授权通过真实可用的GPT-6 Pro入口主动咨询；有在途相同咨询先复用，只有关键证据/目标变化才发送精确增量。沿现有ChatGPT Pro聊天时先read_thread，send_message_to_thread传紧凑正文而非不可读取的本机路径。当前ChatGPT发送schema不承诺可设置/回读模型，不能把Codex的Astra/Sol模型值写成Pro、不能凭标题证明型号；实际身份不可见时保存unknown并说明。收到建议后由主控在授权/可靠预算内形成合同并实际派出，科学越界仍由用户决定。咨询触发、作者自主权与并行见[持续派工与 Pro 解阻](active-dispatch-and-pro.md)。
